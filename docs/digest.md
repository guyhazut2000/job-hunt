# Daily digest

One summary per user per day, saved with full history at **`/digest`** (detail: `/digest/<id>`),
linked from the nav ("More"), the mobile menu and `/notifications`. When there is something to report
it is also sent as a `DIGEST` notification: the full text goes to **Telegram**, the bell links to the
detail page. Quiet days are stored but not sent.

## What's in it

The window is "since the previous digest" (max 7 days back), or the last 24h for the first one.

| Section             | Source                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| New jobs            | `JOB_MATCH` alerts from saved searches + new jobs scoring ≥ 70 on your profile (top 5, untracked). |
| Application updates | Applications whose status (`statusChangedAt`) or hiring stage changed in the window.               |
| Follow-ups due      | Same rule as follow-up reminders (`APPLIED`, untouched for N days).                                |
| Upcoming interviews | `interviewAt` in the next 7 days; counts `INTERVIEW`-status applications with no date.             |
| Learning            | Week minutes vs goal, active days, streak, reviews due, next topic.                                |
| Job scans           | `IngestionRun` failures in the window (your companies first).                                      |

Stored as raw data (`Digest.content`, versioned) and rendered in the viewer's current language, so
switching he/en re-renders old digests. `Digest` has `@@unique([userId, day])` (Israel date).

## "How to streamline your process"

Up to 4 concrete next steps. Generated by Gemini through `guardedLLM("digest")` (same per-user and
app-wide limits and cache as every AI feature) from compact facts only — counts, job titles and
companies; no emails, notes or contacts. If AI is off (`LLM_PROVIDER=mock`), over the limit or
returns something invalid, a deterministic rule set is used instead (prep for the next interview,
batch follow-ups, add missing interview dates, nudge stalled screenings, apply-or-archive old saved
jobs, apply to fresh matches, save a search, fit in study time). `Digest.aiSource` records which
(`ai` / `offline` / `limited`) and the page shows it.

## When

`/api/cron/hourly` (see [notifications.md](notifications.md#timing-honesty-hobby-crons)) generates the
digest on the first run at or after your digest hour (default 08:00 Israel time), at most 40 users
per run. Who gets one: anyone with an application, a saved search or learning progress.
"Generate now" on `/digest` builds/refreshes today's digest immediately (and sends it if not empty —
the `digest:<day>` dedupe key means a refresh is not re-sent).

Quiet hours apply to the Telegram copy (deferred, not dropped); the in-site copy is immediate.

## Settings

`/settings/notifications` → "Daily digest": on/off and hour. Channel toggles for "Daily digest" are in
the kinds table (Telegram on, push off by default — push can't show the long text).

## Telegram

The message is HTML, capped at ~3900 chars (Telegram's limit is 4096): whole sections are dropped from
the middle first, the tips and the link are kept. Requires the Telegram connection in settings.
